# Skills

A skill is a named workflow Freedas can load on demand: a folder with a
`SKILL.md`, or a flat `.md` file. Once discovered it registers as a slash
command (`/<id>`) and the model can load it through the `skill` tool.

## Discovery

Project-scoped skills (`.freedas/skills`, `.claude/skills`, `.agents/skills`)
load only when the project layer is trusted (`trust_project_code` or
`FREEDAS_TRUST_PROJECT_CODE=1`); untrusted sources are skipped with a
warning. A shadowed skill — one whose ID collides with an earlier source —
is flagged in `skill list` at every scope it appears in.

Sources are searched in this order; a later source replaces an earlier skill
with the same ID:

1. `~/.claude/skills`, then project `.claude/skills` from the project root down to the cwd
2. `~/.agents/skills`, then project `.agents/skills` the same way
3. `~/.config/freedas/skills`
4. `.freedas/skills` from the project root down to the cwd
5. Directories named by the `skills` config key (relative paths resolve against the project)

Each source supports root-level `*.md` files (a one-file skill named by its
stem) and directories containing `SKILL.md` up to six levels deep. A
`SKILL.md` folder is one skill; recursion does not continue inside it. Hidden
files are skipped.

A skill does not register if a built-in slash command already owns its name
(see the reserved list in [Slash commands](./slash-commands.md)).

## Format

```markdown
---
name: release
description: Cut a release and write the notes
---
Read the commits since the last tag. Draft the release notes, group them by
feature, fix, and breaking change, then open the pull request. The checklist
is in checklist.md.
```

The frontmatter `name` is the skill ID and slash command; absent it, the
directory name (or file stem) is used. `description` is what the model sees
when deciding to load the skill. The body is the prompt. Other files in the
folder are supporting material the skill body can reference relative to its
own directory.

`metadata.freedas/autogenerated: true` marks a skill the learner wrote; the
learner only replaces an auto-generated skill when the new draft is shorter.

## Skill learner

After a session completes a multi-tool run (3+ tool calls) with
`memory.distill.enabled`, Freedas drafts a skill into
`~/.config/freedas/skills/auto-<slug>/SKILL.md` from the last successful
prompt and result. A hand-written skill with the same ID is never overwritten.

- `freedas skill list --auto` lists learned skills.
- `freedas skill forget <id>` deletes a skill directory from the project or global folder.

## Team registry

`freedas skill list|push|pull` talks to the workspace's skill registry on the
control plane (`/registry/skills/...`), using the stored `control` credential.

```bash
freedas skill list               # registry skills (needs control-plane auth)
freedas skill list --local       # discovered local skills
freedas skill list --auto        # learned skills
freedas skill push <name> [--dir <path>]
freedas skill pull <name> [--global] [--force]
```

`push` packs the directory into a gzip tarball and uploads it with a SHA-256
— registry writes need an owner/admin role on the workspace. `pull` verifies
the hash, requires the registry URL to be HTTPS (loopback exempt), and
extracts to `.freedas/skills/<name>` (or `~/.config/freedas/skills/` with
`--global`), rejecting entries that escape the target directory. If the
target exists and differs, pull refuses without `--force`. `forget` removes
the skill from every root that contains it, not just the first.

The registry base URL comes from `FREEDAS_REGISTRY`, else
`FREEDAS_CONTROL_URL`/`FREEDAS_API_URL` with `/registry` appended, else
`http://127.0.0.1:8080/registry`.
